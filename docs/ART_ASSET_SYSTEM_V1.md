## 本批资产

| 范围 | 来源 | 资产覆盖 |
|---|---|---|
| 3D 角色、敌人、建筑、圣火与拾取物 | `js/world3d.js` 的 `finishModel` 与既有 `GB` 几何构造器 | 49 组已注册模型：英雄身体/披风/帽饰/手持物、敌人、塔与兵营、士兵、圣火形态、金币/石块/晶体 |

本批没有加入外部图片、模型、字体或音频文件，没有下载第三方游戏/素材包资源，也没有把参考截图作为运行资源。3D 网格由项目 Three.js 几何构造器生成，界面图标由项目 Canvas 代码绘制，随游戏本地运行。

## 视觉设计边界

- 延续项目既定的低多边形奇幻守村方向、16:9 横屏和读图优先标准。
- 用三段火纹、黄铜嵌线、青瓷能量点作为本项目自己的贯穿元素。
- 金色只强调奖励/圣火；青蓝强调交互/防御；危险红继续保留给敌人和预警。
- 每张商品卡按稳定 ID 选择具体物件轮廓；保留名称、属性、价格和状态文字，图像用于识别而不取代信息。
- 角色配饰识别度另见英雄美术 PR；本批不改变玩法、数值和购买规则。

## 来源与 AI 使用记录

- 外部素材来源：无。
- 外部模型/纹理生成服务：本批未使用。
- 资产表示：程序几何与 Canvas 矢量路径，源代码随 Git 提交保存。
- AI 使用：本批为 AI 辅助编写/细化美术代码；游戏内的模型形状和图标为预生成并随游戏提供的可见内容。负责人需要在 Steam Content Survey 中根据最终发行构建如实评估并披露；“没有外部图片”不代表“没有 AI 辅助美术”。
- 运行时生成式 AI：本批没有。

## 可追溯与审阅门槛

1. 保留本批分支、提交和文件历史；资产修订按稳定 ID 留在源代码中，不覆盖成来历不明的二进制文件。
2. CI 的 `npm run shots` 截图应作为首轮视觉证据；负责人审阅 1280×720 横屏下的英雄、敌人、圣火、建筑和整备卡，确认没有遮挡、轮廓混淆或性能回退。
3. 只有在截图审阅通过后，才把状态从 `CANDIDATE_ONLY` 改为已验收；未通过的造型继续修订。
4. 后续如导入 AI 生成或第三方网格，逐项登记服务/模型版本、生成日期、当日商用条款、输入参考、原始输出、人工重构内容、哈希与相似性审查；缺少可核验授权时不得进入发行构建。
5. 不以“人工改过”“使用付费工具”或“Steam 问卷已填写”作为版权无争议的结论。是否享有可主张的版权、保护范围以及侵权风险，仍取决于人类表达贡献、具体法域和事实审查。
