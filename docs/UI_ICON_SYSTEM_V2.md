## 目标和边界

让玩家从标题进入游戏、完成整备、战斗、暂停、结算、查看纪录时，都能靠图形快速认出操作类别。现在已有金币、复活次数、部分英雄与圣火形态图形；其余不少按钮、战斗技能、设置和兵营指令仍以文字为主，需要补齐。

图标是文字标签的视觉锚点，**不删掉中文名称、价格、按键说明或效果解释**。图标不能只靠颜色表达含义。所有图形在代码中以 Canvas 路径和基础几何绘制；不新增图片、模型、字体、音频或外部图标库。图形须原创，不临摹商业游戏、现成素材包或其专属徽记。

## 视觉语言

### 色彩与同屏配额

| 语义 | Bible token / 色值 | 硬性限制 |
|---|---|---|
| 圣火值、英雄 | `FLAME_GOLD` / `#FFB547` 满亮 | 满亮暖金只给圣火值与英雄，不作通用高亮、焦点、选中描边或装饰 |
| 常规图标外轮廓 | `ICON_BRASS` / `#9B7447` | 只作 2px 主体轮廓；不得替代金币、焦点或选中 token |
| 金币 | `COIN_BRASS` / `#C18A45` | 降饱和黄铜，只表示金币及与金币直接关联的计价符号 |
| 焦点括号 | `FOCUS_PARCHMENT` / `#E8D9B5` | 只画四角 L 形括号；不得改用 `FLAME_GOLD` 或月青 |
| 选中描边 | `SELECT_BRASS` / `#B9894F` | 只用于选中态 3px 状态描边，不作图标常规外轮廓 |
| 敌人 | `ENEMY_PURPLE` / `#6B3FA0` 身体 + `ALERT_RED` / `#FF3B3B` 眼点 | 所有敌人类图标（含夜战）统一冷紫身体、红眼点 |
| 来袭、遭袭 | `ALERT_RED` / `#FF3B3B` | 只用于边缘来袭箭头与遭袭警示，不用于普通按钮、价格或装饰 |
| 危险按钮 | `DANGER_CLAY` / `#A8483A` + 裂纹 | 必须同时有裂纹造型，不能只靠颜色表达危险 |
| 寒霜、法力、夜 | `MOON_CYAN` / `#5FA8C8` | 不作悬停、键盘或手柄焦点色 |

上表只抄录上位 handoff 内《FG_ART_BIBLE_001》已经定义的 token/值；中性木、铁、墨色也只能引用该圣经既有 token，本文件不得派生、混色或新增近似十六进制值。一个 HUD 画面内的高饱和色块不得超过 **3 块**；超额内容降明度、降饱和或改用中性底板。图标不能只靠颜色传义，关闭颜色后仍须由轮廓、明度和符号识别。

### 造型、线宽与底板

- 每枚图标采用“**一个主剪影 + 至多两个识别细节**”，造型简洁、圆润、厚实，呈木雕、铸金徽章和火晶的手作感；禁止细线写实、现代办公软件符号和繁复纹章。
- 图标主体外轮廓统一 **2px `ICON_BRASS` 黄铜描边**，内部细节 **1.5px**；仅 16 档内部细节降为 **1px**。所有折角使用 `round join`。黄铜描边外再外扩 **1px 本色压暗隔离边**，确保明暗背景均清楚。
- 底板只允许三类：**木牌烙刻、圆木盘（金环 + 铆钉）、盾牌徽章**。禁止圆角矩形图标底板。面板外框由九宫格承担，图标不得再叠第二圈金边。
- 按钮图标优先位于中文标签左侧；纯图形战斗按键居中。键盘字母、手柄键位是独立提示，不画进图标本体。

### 尺寸网格与界面档位

只使用 **16 / 24 / 32 / 48** 四档逻辑像素网格。16 档仅供状态角标；组合图标最小为 24，不得把两个完整语义挤进 16。主剪影占单元约 65%–75%，对齐整数或半像素，使 1 倍像素比描边清晰。

| 界面位置 | 档位 | 用途与限制 |
|---|---:|---|
| 状态角标、锁、对勾、“缺”、“新” | 16 | 仅单一覆盖语义；不得作为主图标 |
| HUD 数值、信息卡分类、键鼠/手柄提示、教程提示 | 24 | 组合图标的最小档；保留相邻文字或数值 |
| 战斗技能、建造与兵营指令、列表按钮 | 32 | 高频操作默认档；覆盖层不得遮挡主识别特征 |
| 英雄/地图/物品大卡、结算徽章、桌面应用图标母版 | 48 | 先以 48 母版定剪影，再分别简化到小档，不做等比硬缩 |

布局与图标验收基准统一为 **960×540 逻辑画布、1 倍像素比**；`docs/ART.md` 所说的 1280×720 是同一 16:9 逻辑画面的截图输出尺寸（整体按 4/3 倍缩放），不是另一套布局坐标。四档逐一检查整数对齐、轮廓闭合与灰度可辨；通过标准是去色后仍能区分类别、操作和状态，而不是只在高分屏放大图中好看。

### 开局流程：英雄、地图、危险与变异器

- **10 个英雄**（`hero:<id>`）每人使用自己的头像剪影，选人小徽记不能全复用一个通用人头：
  `mage` 法师＝尖帽与法杖星；`ranger` 弩手＝兜帽与弩；`knight` 盾骑士＝面甲与盾；`rogue` 影刺客＝双尾头巾与双匕；`engineer` 工匠＝护目镜与扳手；`berserker` 狂战士＝角盔与斧；`priest` 圣女＝光环与圣典；`bomber` 爆破手＝引线炸弹；`merchant` 商人＝高礼帽与钱袋；`gambler` 赌徒＝王冠与骰子。使用各英雄既有流派色，锁定时仍保留可识别剪影并叠加小锁。
- **4 张地图**（`map:<id>`）：`village` 圣火村＝屋顶/木桥；`forest` 林缘营地＝松树/营火；`snow` 雪岭关隘＝山脊/冰桥；`marsh` 沼泽渡口＝芦苇/小舟。轮廓和地形要素各自不同。
- **危险等级**（`danger:<0–5>`）：盾牌上逐级增加尖齿/裂纹，从空盾至六阶标记；保留阿拉伯数字与文字，不只用红色深浅表示等级。危险色仅出现在本组和确有危险的警示上。
- **8 个变异器**（`mut:<id>`）：`night` 月牙；`swarm` 多个小敌影；`iron` 板甲盾；`poor` 裂币；`fragile` 裂盾/心；`horde` 叠层敌影；`lonely` 孤立圆环；`nobuild` 交叉锤。启用态加实心内芯或勾选角标，禁用态保留完整轮廓。

### 桌面与 Steam 应用图标

- Windows `.exe` 与 Steam 应用图标均由代码生成，母版语义为“盾牌徽章中的圣火”，遵守 48 档主剪影、2px `ICON_BRASS` 黄铜描边和 1px 本色压暗隔离边；各平台尺寸单独像素对齐，不以浏览器缩放代替。
- 应用图标不得引入图片源、外部图标库或新增字体；除 A+ 允许的一款 OFL 子集字体外不新增素材。小尺寸只保留圣火、盾牌两层语义，去掉铆钉等易糊细节。

### 设置、按键、结算、纪录与成就

- 设置项 ID 对应：`vol` 扬声器；`music` 音符；`sfx` 锤击火星；`shake` 震动波纹；`flash` 太阳射线加减幅环；`fx` 星形特效；`nums` 浮动伤害刻度；`ring` 脚下定位环；`gfx` 三层画质晶片；`cam` 镜头准星；`cb` 高对比双色盾；`blur` 窗口加暂停标记。开关、滑杆和当前数值仍要用文字/刻度显示。
- `keys` 用键盘轮廓；`keyset:<action>` 用单键帽加更改箭头；`keysReset` 复位箭头。14 个可改操作按移动方向、冲刺、三技能、造塔、四种兵营指令、暂停分组；平台按键提示动态显示，不做死图。
- 结算：胜利用完整圣火冠/桂冠，失败用熄火裂盾，无尽用无限环；击杀、金币、位阶、连杀、伤害构成分别沿用对应 HUD 图标。
- **42 个成就**按目标类型做可区分的小徽章：局数/波次＝旗与刻度；Boss/击杀＝敌影/断刃；通关/危险＝圣火盾与阶级齿；英雄/解锁＝英雄面具；无尽＝无限环；武器进化/流派＝武器与分叉星；圣火等级/祭坛＝火晶/石坛；建筑/金币/祝福/变异器/每日＝塔、钱袋、光环、变异环、日历。相近阶梯（例如 1k/10k/50k 击杀）在同一主题徽记上用明确层级角标区分。未解锁态用暗化剪影加锁，获得态加小勾/亮边。

## 状态规范

任一状态至少同时使用 **造型、明度、文字**三类线索中的两类；颜色和动画只能加强，不能成为唯一线索。覆盖层实时绘制，但不得破坏主剪影。

**线宽统一：** 2px 是图标主体轮廓；选中态的 3px 是控件最外层状态描边，必须**替换**控件原有边框而不是叠加第二圈，也不改变图标主体的 2px 轮廓。1px 本色压暗隔离边仍贴着图标主体，不计入 3px 状态描边。

| 状态 | 必备表现 | 双线索核验 |
|---|---|---|
| 焦点 | 四角 **L 形 `FOCUS_PARCHMENT` 括号**，周期 **1.2 秒**的轻微明暗呼吸 | 括号造型 + 明度动画；禁止用月青作焦点色 |
| 选中 | 底板内凹、**3px `SELECT_BRASS` 状态描边**、16 档对勾 | 深度/明度 + 描边/对勾 |
| 按下 | 整体缩放至 **0.96**，并下移 **1px** | 尺寸 + 位移 |
| 冷却 | 从 12 点方向**顺时针暗扇形**扫过，中央显示剩余秒数；就绪时闪亮 **0.2 秒** | 暗扇造型 + 数字文字；就绪闪仅作补强 |
| 缺资源 | 图标亮度降至 **70%**，价格保持正常中性文字色，并叠 16 档“**缺**”角标 | 明度 + 文字角标/价格 |
| 未解锁 | 主图变为单色暗影，叠 16 档锁；锁对主剪影遮挡面积 **≤40%** | 明度/去色 + 锁造型 |
| 禁用 | 保留可辨主剪影并叠斜杠 | 明度 + 斜杠造型 |
| 新获得 | 叠 16 档“**新**”角标 | 文字 + 角标造型；不得只靠跳动或亮色 |

“未解锁”与“禁用”不可共用同一图：前者说明取得条件，后者说明当前不可操作。多个状态并存时，交互状态（焦点/按下）在最外层，信息状态（冷却/缺资源）居中，收藏状态（锁/新）固定角位；同一位置不得堆叠两个角标。

## 夜战约束与缩略验收

- 夜战 HUD 只有**圣火值图标**可保持满亮，其余图标亮度不超过 **80%**；战斗底板不透明度不得低于 **85%**。
- 图标禁止使用 `shadowBlur` 发光。需要强调时使用实色轮廓、呼吸明度或状态覆盖层，避免暖光争夺圣火焦点。
- 所有敌人类图标在夜战仍统一为 `#6B3FA0` 冷紫身体 + `#FF3B3B` 红眼，不随环境改成暖色。
- 夜战验收截图先按 960×540、1 倍像素比生成，再缩至 **231×87**；缩略图中最亮暖点必须仍是圣火，来袭红箭头只在事件发生时成为局部警报，不得形成常驻暖色中心。

## 绘制与接入约定

1. 每个图标实现为无外部状态副作用的纯绘制函数 `draw(ctx, size)`；稳定 ID 注册表示例为 `hero.mage`、`map.snow`、`mod.trident`、`action.repair`、`setting.cb`。只按 ID 映射，不得按中文显示文本匹配；缺失映射必须被审计发现。
2. 主体拆成“主体剪影、类别色、状态覆盖层”。主体按 **ID + 档位 + 像素比**烘焙到离屏图集，单色暗影版也预烘焙；禁止运行时使用 `ctx.filter`，以兼容保留的微信分支。焦点、选中、按下、冷却、缺资源、锁、禁用与“新”覆盖层实时绘制。
3. 图集采用懒加载：首次出现时才生成对应 ID/档位/像素比条目，不预热全目录。记录烘焙数量、缓存命中/未命中、图集占用与单屏绘制开销，并将统计写入 `docs/AUDIT.md`。
4. 先覆盖所有可点击按钮和战斗热区，再覆盖卡片、状态数值、统计和成就；保持原点击区域，不因图标挤压价格、名称、说明或按键提示。
5. 所有图标、状态角标与教程提示都不得进入中央战场禁入区 **x=240–720、y=135–405**（960×540 逻辑坐标）。边缘提示从其锚点向画面外侧弹出；`audit:ui` 必须把禁入区侵入、越界、重叠或向内弹出任一项记为**失败并返回非零退出码**，不得只写报告。
6. `audit:ui` 必须以 960×540、1 倍像素比逐屏检查标题/开局、整备、战斗 HUD、兵营、暂停、设置/改键、复活、结算、纪录/成就，同时覆盖鼠标、键盘和手柄焦点；并强制生成同一战斗构图的日战、夜战与 231×87 夜战缩略图。缺任一截图、夜战非圣火暖点最亮、战斗底板低于 85%，或缩略图圣火不再是最亮暖点，均使审计失败并返回非零退出码。
7. `docs/ART.md` 的 1280×720 评审截图由 960×540 逻辑画布整体缩放输出；禁入区检测始终使用 960×540 坐标，截图中对应区域为 **x=320–960、y=180–540**，不得直接拿 1280×720 像素值回写布局。

## 完成标准

- 每个可交互控件都有与动作一致的图标；标题进入流程、战斗 HUD、整备、设置、结算和记录全覆盖。
- 所有当前英雄、地图、危险级别、变异器、武器、技能、建筑、兵种/阵型、道具、祝福、圣火形态、成就都有 ID 对应图形。
- 中文标签与操作/价格/效果信息仍可读；任何状态不靠颜色单独传意。
- 键鼠和手柄提示不遮挡图标；不同窗口缩放下保持比例、轮廓和点击区域。
- 无新增外部资产或依赖；截图可见，项目 UI 审计通过。
