## 目标和边界

让玩家从标题进入游戏、完成整备、战斗、暂停、结算、查看纪录时，都能靠图形快速认出操作类别。现在已有金币、复活次数、部分英雄与圣火形态图形；其余不少按钮、战斗技能、设置和兵营指令仍以文字为主，需要补齐。

图标是文字标签的视觉锚点，**不删掉中文名称、价格、按键说明或效果解释**。图标不能只靠颜色表达含义。所有图形在代码中以 Canvas 路径和基础几何绘制；不新增图片、模型、音频或外部图标库，字体沿用 `AGENTS.md` 已授权的 OFL 子集，本规范不增加新字体。图形须原创，不临摹商业游戏、现成素材包或其专属徽记。

## 视觉语言与尺寸

- 图标必须延续圣经规定的木牌烙刻、木框金边、厚实剪影。所有轮廓在 960×540 逻辑画布上设计；不得按 1280×720 重新排版，也不得用默认圆角矩形做图标底板。
- 图标色值仅从下表取值，不增加私有色。透明度只用于降低表中颜色的亮度，不得借混色产生新语义色。

| 颜色名 | 色值 | 允许用途 | 禁止用途 |
|---|---|---|---|
| 圣火金 | #FFB547 | 满亮度只用于圣火值图标、英雄图标；其他图标仅可用降至 80% 或以下的金色外轮廓 | 金币、普通奖励、焦点或其他图标不得用满亮度 |
| 余烬橙 | #E8702A | 圣火与英雄图标的次级暖色 | 其他图标、普通奖励、警告按钮 |
| 暖土黄铜 | #C9A27A | 金币与经济数值，作为降饱和黄铜色；亮度最多为圣火金的 80% | 圣火值、英雄主图形、危险提示 |
| 草地绿 | #6F9A4E | 草药、自然、收成类图标的小面积语义填色 | 焦点、选中、危险 |
| 屋顶赭红 | #A8483A | 危险操作按钮的木牌底色，并必须配裂纹形状 | 普通敌人身体、焦点 |
| 木色 | #7A5234 | 烙刻木牌、木框和暗色承托 | 高亮焦点 |
| 夜蓝 | #1E2A4A | 深色底板、夜战底色 | 语义状态单独表达 |
| 月青 | #5FA8C8 | 只表示寒霜、法力与夜晚 | 焦点、普通选中、危险 |
| 敌紫 | #6B3FA0 | 敌人身体和敌对轮廓；保持冷色主剪影 | 非敌人类别 |
| 警报红 | #FF3B3B | 敌人眼睛的小面积标记、来袭边缘箭头 | 危险按钮底色、普通红色填充 |

- 所有图标外轮廓统一 2 逻辑像素金色描边，内部细节统一 1.5 逻辑像素；不得按图标尺寸缩放线宽。内部细节不得削弱主剪影。
- 固定四档：16×16 只作状态角标；24×24 用于按钮与 HUD；32×32 用于技能、武器和建造项；48×48 用于英雄、地图与成就。24×24 及以下只画主剪影，不画内部纹样；角标作为独立状态层叠加。
- 敌人图标以敌紫身体为主：杂兵小而圆、精英高而带尖刺、重甲宽而矮重，Boss 用明显更大的冠脊/角甲剪影。眼睛只用警报红作小点，不得把敌人整体涂红。
- 塔图标必须照阶段 2 最终模型的塔顶侧面剪影绘制，阶段 2 定稿并验收前不定稿塔图标。当前实际塔 ID 只有 sentry、pylon、siphon、barracks；游戏没有炮塔，目录和实现不得增加炮塔。
- 只允许三种底板：烙刻纹样木牌（菜单与危险按钮）、战斗用圆木盘加金环（战斗快捷操作）、卡片盾牌徽章（英雄、地图、成就与物品卡）。危险按钮的烙刻木牌使用屋顶赭红与裂纹。禁止圆角矩形、胶囊形或另造第四种通用底板。
- 标题菜单的“开始守护”按钮选中态对照 FG_CONCEPT_01_V002.png：左侧竖排木牌菜单、清楚的烙刻与克制金边；不得把概念图当作可直接导入的素材。

## HUD 层级与中央安全区

- 常驻 HUD 按圣经分层：左上圣火值、英雄生命与法力；右上波次与倒计时；底部中间建造栏，右下技能栏。选中单位卡放在右下情境层；教程与提示只放顶部横幅或右侧卷轴。
- 逻辑屏幕中央安全区固定为 x=240–720、y=135–405，边界按闭区间处理。任何 UI 图标、图标状态角标和弹出提示的包围盒都不得与该区域相交；战场单位、地图和场景特效不属于 UI 图标。
- 来袭预警只用红色方向箭头，贴屏幕边缘朝向来袭方；箭头不能进入中央安全区，也不能靠色彩单独表达方向，需保留箭头形状与方向。
- 夜战 HUD 中只有圣火值图标可用满亮度圣火金。其他图标的可见亮度不超过圣火值图标的 80%，不泛光。英雄图标仅在非战斗的选人/卡片中允许满亮度；进入战斗 HUD 后也服从 80% 上限。
- 夜战敌人图标以敌紫等冷色为主体；警报红只保留在红眼小点和来袭箭头上，红眼不发光、不超亮。夜战截图中，最亮的暖色点必须是圣火值图标。
- 验收画面按逻辑尺寸 960×540、设备像素比 1、原色和灰度各检查一次；图标在灰度下仍能凭轮廓、切口、方向或标记辨认。

### 开局流程：英雄、地图、危险与变异器

- **10 个英雄**（`hero:<id>`）每人使用自己的头像剪影，选人小徽记不能全复用一个通用人头：  
  `mage` 法师＝尖帽与法杖星；`ranger` 弩手＝兜帽与弩；`knight` 盾骑士＝面甲与盾；`rogue` 影刺客＝双尾头巾与双匕；`engineer` 工匠＝护目镜与扳手；`berserker` 狂战士＝角盔与斧；`priest` 圣女＝光环与圣典；`bomber` 爆破手＝引线炸弹；`merchant` 商人＝高礼帽与钱袋；`gambler` 赌徒＝王冠与骰子。英雄只靠帽饰与手持物剪影区分；图标填色只取本规范色表。锁定时保留可识别剪影并叠加状态矩阵规定的小锁。
- **4 张地图**（`map:<id>`）：`village` 圣火村＝屋顶/木桥；`forest` 林缘营地＝松树/营火；`snow` 雪岭关隘＝山脊/冰桥；`marsh` 沼泽渡口＝芦苇/小舟。轮廓和地形要素各自不同。
- **危险等级**（`danger:<0–5>`）：盾牌上逐级增加尖齿/裂纹，从空盾至六阶标记；保留阿拉伯数字与文字，不只用红色深浅表示等级。危险按钮以屋顶赭红木牌加裂纹表示。
- **8 个变异器**（`mut:<id>`）：`night` 月牙；`swarm` 多个小敌影；`iron` 板甲盾；`poor` 裂币；`fragile` 裂盾/心；`horde` 叠层敌影；`lonely` 孤立圆环；`nobuild` 交叉锤。启用态加实心内芯或勾选角标，禁用态保留完整轮廓。

### 稀有度与调试总览

- 稀有度标记使用 16×16 角标：普通为无附加齿；精良一处切口；稀有两处切口；传说三处切口加小冠形缺口。只用轮廓数量区分，不新增色值，也不使用满亮度圣火金。
- 开发态提供图标总览页，列出稳定 ID，并预览 16/24/32/48 档、灰度和全部状态；不得出现在正式玩家流程或安装包入口。

## 状态规格

状态叠加在稳定 ID 图形之上。各状态至少通过造型、亮度、标记文字三种通道中的两种表达；状态角标不改变主图标 ID，也不靠颜色单独表达。

| 状态 | 必须使用的造型 | 亮度 / 动效 | 文字或标记 |
|---|---|---|---|
| 默认 | 保留完整主剪影与对应底板 | 按当前昼夜亮度规则 | 保留原中文名称与数值 |
| 焦点 | 图标四角出现四个分离的金色括号，不能套整圈外框 | 900ms 呼吸一次，只调整亮度；无泛光。夜战范围为圣火金 72%–80% | 同时显示当前输入设备焦点提示 |
| 选中 | 底板内凹 1px，主体向下压入；图形内加对勾 | 对勾不闪烁，亮度不超过当前场景上限 | 对勾是固定标记 |
| 冷却 | 暗色扇形遮罩按剩余比例扫过图形 | 遮罩亮度低于主剪影，不使用滤镜 | 中央显示剩余秒数 |
| 金币不足 | 主图形保留但整体压暗，右上角挂小缺口角牌 | 主图形亮度降到正常态的 45% | 角牌明确写“缺”，价格与差额仍可见 |
| 未解锁 | 暗影轮廓，不绘制内部细节；剪影仍能辨类 | 主图形亮度为正常态的 35% | 右下角加闭合小锁 |
| 禁用 | 主图形加一条左上至右下斜杠 | 亮度为正常态的 45% | 斜杠不可与冷却扇区混淆 |
| 按下 | 木牌/圆盘出现压入边，图标下移 1px | 亮度短暂降至正常态的 85% | 动作说明和按键提示保留 |

焦点括号与选中态不能复用同一外框；未解锁必须使用锁，金币不足必须使用“缺”角标，两者不能互相代替。图中文字角标不直接嵌入图标路径：实现“缺”后必须重新生成字体子集并通过 npm run check。项目的 tools/fonts.js 会从 js/ 和 preview.html 收集实际字符；若新增角标字不在子集中，先运行 npm run fonts。

## 绘制、缓存与 audit:ui 接入约定

1. 用稳定 ID 注册图标；任何缺少映射的当前数据 ID 都要让审计失败，禁止静默回退到文字或空白。所有图标只用 Canvas 路径/基础几何绘制，不导入图片、模型、音频或第三方图标库。
2. 按“图标 ID × 尺寸档（16/24/32/48）× 静态状态层”预先绘制到离屏图集；每帧只执行 drawImage 贴图，不重画路径。未解锁暗影、锁、斜杠等状态变体同样预绘制。禁止使用 ctx.filter，兼容保留的微信分支。
3. 图标状态矩阵中的扇形冷却遮罩和焦点呼吸可作为单独动态覆盖层；主体剪影和静态暗影仍来自缓存。不要在逐帧循环里生成路径、离屏 Canvas 或图集。
4. 扩展 tools/uiaudit.js 的采集信息：图标绘制入口必须上报逻辑画布包围盒；每个教程/弹出提示上报最终包围盒。audit:ui 对 17 个界面逐个检查，任一图标或提示框与 x=240–720、y=135–405 相交即失败，并输出屏幕名、稳定 ID 与重叠坐标。只检查 UI 标记对象，不把战场单位或地图对象误报成 HUD。
