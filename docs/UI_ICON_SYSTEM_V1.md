**状态：** 美术规范已定，运行时实现待工程接手  
**基线：** PR #3 当前 head `0f5563a984f15e7e7ab7026448f00e50b2a0b8ec`  
**职责：** Codex 定义图形语言与验收；Claude 实现跨界面的图标注册表和绘制；GPT 继续负责文案及小幅排版调整。

## 目标和边界

让玩家从标题进入游戏、完成整备、战斗、暂停、结算、查看纪录时，都能靠图形快速认出操作类别。现在已有金币、复活次数、部分英雄与圣火形态图形；其余不少按钮、战斗技能、设置和兵营指令仍以文字为主，需要补齐。

图标是文字标签的视觉锚点，**不删掉中文名称、价格、按键说明或效果解释**。图标不能只靠颜色表达含义。所有图形在代码中以 Canvas 路径和基础几何绘制；不新增图片、模型、字体、音频或外部图标库。图形须原创，不临摹商业游戏、现成素材包或其专属徽记。

## 视觉语言

- 延续《圣火守护者》的暖色低多边形奇幻风格：简洁、圆润、厚实的剪影，像木雕、金属徽章和火晶制成；避免细线写实、现代办公软件风格和花哨纹章。
- 每枚图标采用“**一个主剪影 + 至多两个识别细节**”。普通操作放在深色圆角底板上；物品/英雄卡可用小型盾牌或炉石形徽章承托。不要给每个按钮都套金边。
- 最小主图形尺寸为逻辑画布 18×18；常用 24×24，圆形战斗按键约 28×28。主要剪影占单元约 65%–75%，描边粗细按尺寸缩放，缩小后不能糊成一团。
- 使用当前主题色和对象原有色：金色只表示金币、奖励、圣火资源；红色只表示危险、受伤和不可逆风险；青蓝用于交互焦点/防御提示；英雄与物品类别可用数据中的既有色。灰度、色弱辅助下仍须靠形状区分。
- 按钮图标优先置于中文标签左侧；战斗圆形按键的图标居中，按键提示独立显示在边缘，不把键盘字母画进图标本体。

### 开局流程：英雄、地图、危险与变异器

- **10 个英雄**（`hero:<id>`）每人使用自己的头像剪影，选人小徽记不能全复用一个通用人头：  
  `mage` 法师＝尖帽与法杖星；`ranger` 弩手＝兜帽与弩；`knight` 盾骑士＝面甲与盾；`rogue` 影刺客＝双尾头巾与双匕；`engineer` 工匠＝护目镜与扳手；`berserker` 狂战士＝角盔与斧；`priest` 圣女＝光环与圣典；`bomber` 爆破手＝引线炸弹；`merchant` 商人＝高礼帽与钱袋；`gambler` 赌徒＝王冠与骰子。使用各英雄既有流派色，锁定时仍保留可识别剪影并叠加小锁。
- **4 张地图**（`map:<id>`）：`village` 圣火村＝屋顶/木桥；`forest` 林缘营地＝松树/营火；`snow` 雪岭关隘＝山脊/冰桥；`marsh` 沼泽渡口＝芦苇/小舟。轮廓和地形要素各自不同。
- **危险等级**（`danger:<0–5>`）：盾牌上逐级增加尖齿/裂纹，从空盾至六阶标记；保留阿拉伯数字与文字，不只用红色深浅表示等级。危险色仅出现在本组和确有危险的警示上。
- **8 个变异器**（`mut:<id>`）：`night` 月牙；`swarm` 多个小敌影；`iron` 板甲盾；`poor` 裂币；`fragile` 裂盾/心；`horde` 叠层敌影；`lonely` 孤立圆环；`nobuild` 交叉锤。启用态加实心内芯或勾选角标，禁用态保留完整轮廓。

### 战斗 HUD、快捷操作与建筑

| 内容 / 稳定 ID | 图形设计 |
|---|---|
| 玩家生命、法力 | 心形；法力用分层火晶/水滴。旁边必须保留数值或明确刻度 |
| 圣火生命、警报 | 炉火包盾；遭袭状态配外扩警示环和短促脉冲，不只闪红 |
| 波次、倒计时、击杀、连杀、建筑数 | 波次旗、沙漏、敌影徽章、连击弧线、四角塔基；数字继续可见 |
| 金币碎片、复活余次、奖励 | 碎晶钱币、独立火苗计数、奖励星章；遵守金色语义 |
| `pause`、`dash`、`skill:0..2`、`build` | 暂停柱；疾行靴和两道位移尾迹；依所装技能 ID 取对应技能图；蓝图加锤 |
| `bt:sentry`、`bt:pylon`、`bt:siphon`、`bt:barracks` 及对应科技卡 | 箭塔＝弩箭/塔顶；寒霜塔＝晶簇/减速环；聚金桩＝漏斗/金币；兵营＝旗帜/盾兵。科技卡沿用本体图形并加罗马数字等级角标 |
| `cmd:post`、`cmd:recall`、`cmd:troop`、`cmd:form` | 插旗布防；回营箭头；盾/枪/弓随当前兵种变化；圆阵/横列/散阵分别用圆点环、直列、疏散点阵 |
| `statsHelp`、属性/统计 | 放大镜加刻度；属性徽记依伤害、生命、防御、速度等类别取对应小图，不堆一排纯文本属性名 |

手柄与键鼠提示独立于主图标：跟随当前输入设备显示键帽或手柄按键/肩键；不能让提示遮住技能图。冷却用环形扇区，资源不足用锁定/欠费标记，选中和键盘焦点有清楚的外框。

### 设置、按键、结算、纪录与成就

- 设置项 ID 对应：`vol` 扬声器；`music` 音符；`sfx` 锤击火星；`shake` 震动波纹；`flash` 太阳射线加减幅环；`fx` 星形特效；`nums` 浮动伤害刻度；`ring` 脚下定位环；`gfx` 三层画质晶片；`cam` 镜头准星；`cb` 高对比双色盾；`blur` 窗口加暂停标记。开关、滑杆和当前数值仍要用文字/刻度显示。
- `keys` 用键盘轮廓；`keyset:<action>` 用单键帽加更改箭头；`keysReset` 复位箭头。14 个可改操作按移动方向、冲刺、三技能、造塔、四种兵营指令、暂停分组；平台按键提示动态显示，不做死图。
- 结算：胜利用完整圣火冠/桂冠，失败用熄火裂盾，无尽用无限环；击杀、金币、位阶、连杀、伤害构成分别沿用对应 HUD 图标。
- **42 个成就**按目标类型做可区分的小徽章：局数/波次＝旗与刻度；Boss/击杀＝敌影/断刃；通关/危险＝圣火盾与阶级齿；英雄/解锁＝英雄面具；无尽＝无限环；武器进化/流派＝武器与分叉星；圣火等级/祭坛＝火晶/石坛；建筑/金币/祝福/变异器/每日＝塔、钱袋、光环、变异环、日历。相近阶梯（例如 1k/10k/50k 击杀）在同一主题徽记上用明确层级角标区分。未解锁态用暗化剪影加锁，获得态加小勾/亮边。

## 绘制与接入约定

1. 建立以稳定 ID 为键的图标注册表（例如 `hero.mage`、`map.snow`、`mod.trident`、`action.repair`、`setting.cb`）。只按 ID 映射，不能按中文显示文本匹配；新增数据 ID 若没有映射应被审计发现，不能静默退化成文字或空白。
2. 将图标拆为“主体剪影、类别色、状态覆盖层”三层。状态至少包括默认、悬停/手柄焦点、选中、按下、禁用/未解锁、冷却/资源不足、已获/新解锁。色弱模式下靠轮廓、线型或标记仍能区分。
3. 先覆盖所有可点击按钮和战斗热区，再覆盖卡片、状态数值、统计和成就；保持信息层级和原有点击区域，不因加图标挤压价格、名称、说明文字。
4. 以 1280×720 横屏检查标题/开局流程、整备、战斗 HUD、兵营指令、暂停、设置/改键、复活、结算、纪录/成就等全部界面；全程检查鼠标、键盘焦点和手柄焦点。至少核对项目现有 17 屏 UI 审计，不重叠、不裁切、不遮挡交互提示。
5. 代码实现后由工程运行 `npm run audit:ui`、流程与截图检查；提交 PR 附各界面截图。通过前标为候选图形，不能宣称全 UI 图标已验收。

## 完成标准

- 每个可交互控件都有与动作一致的图标；标题进入流程、战斗 HUD、整备、设置、结算和记录全覆盖。
- 所有当前英雄、地图、危险级别、变异器、武器、技能、建筑、兵种/阵型、道具、祝福、圣火形态、成就都有 ID 对应图形。
- 中文标签与操作/价格/效果信息仍可读；任何状态不靠颜色单独传意。
- 键鼠和手柄提示不遮挡图标；不同窗口缩放下保持比例、轮廓和点击区域。
- 无新增外部资产或依赖；截图可见，项目 UI 审计通过。
