## 二、需求汇总（去重后）

### 玩法
1. 进化不再三阶封顶：八阶，前中期拿得到，封顶留给长局；打怪给进化经验；采收桩能把远处的进化球吸过来。（Cursor 本地已做，待推送）
2. 难度曲线：前两波以杂兵为主，第 3–4 波起加压并开始有失败压力；前 3 波一次免费保底；Boss 大约每 5 波一次。
3. 商店要回答「下一波具体是什么威胁」，让人想花钱。
4. 兵种更多，覆盖经典即时战略的职能（治疗、侦查、反甲、范围、召唤等），名字和造型全部原创。
5. Steam 版：每局一次免费复活，没有「看广告刷新」；广告位保持空。
6. （Cursor 已做，`f54c6b9`）每个英雄三个技能 Q / E / R，左上红（生命）蓝（法力）双圆槽；圣火可升级，升级后王旗外推、镜头拉远、怪在旗附近刷；开箱召唤同伴，两个同星合成升星，最多 6 个；数值曲线 `RW.SHEET`（怪血前慢后陡、护甲递减、近战/远程/法术分类）。
7. **平衡隐患（Claude 实测，2026-09-24，每英雄 6 局，最多 16 波）**：10 个英雄平均 7.8–9.3 波，彼此很接近；但几乎全部卡在第 9–11 波，60 局里 38 局是圣火被打灭。第 10 波（Boss）前后是一堵硬墙，压力集中在守家而不是英雄。全面升级时要把这段曲线拉平，并让英雄差异体现在打法上。
   - **已处理（M1）**：血量曲线去掉第 8 波后的平方项，圣火与建筑加上防御成长 `RW.SHEET.def`。聪明买机器人危险 0 通关率 58%（目标 40–60%）。英雄差距还有 5 波（目标 3 波），留到下一轮。详见 `docs/WHITEPAPER.md` 6.4。

### 美术与界面
8. **整备页图像化**：每张可购买卡（武器、技能、科技、34 件道具）都要有可辨认的物件图；维修、加固、刷新、开始下一波要有图标；选中、已购、锁定、金币不足状态清楚。
9. **圣火神龛**（美术 P0）：实体火焰成为模型主体，低生命时火焰变短变暗、符纹转红。
10. 战斗配色（P1）：敌人统一暗紫/石色，靠轮廓区分；友方统一暖石、旧铜、木色。
11. HUD 视觉统一（P2）：去掉科幻青色扫描，改成石、木、铜的村庄风格。

## 三、目标架构

现在的结构（一个全局 `RW`、脚本按顺序加载、所有界面在一块 Canvas 上手画）适合小原型，但已经在拖慢三方协作：
每个人都在改同几个大文件（`world3d.js` 900 行、`ui.js` 700 行、`sim.js` 2200 行），界面加图片、加英文、加手柄都很费劲。

### 分层

```
src/
  core/        纯逻辑：战斗模拟、经济、进化、波次、解锁（可在 Node 里无头运行、可单测）
  content/     数据表：heroes / weapons / items / enemies / waves / towers / music 各自一个文件
  render/      Three.js：场景、模型工厂（每类模型一个文件）、特效、镜头、光照预设
  ui/          界面：HTML + CSS 叠在 3D 画面上（取代 Canvas 手画）
  audio/       音乐编曲表 + 合成器 + 音效库
  input/       动作映射：键盘 / 鼠标 / 手柄 → 移动、冲刺、技能、造塔、菜单导航
  platform/    存档（带版本号与迁移）、设置、Electron 桥、Steamworks（成就、云存档）
  i18n/        中文 / 英文文案表
assets/icons/  整备页物件图与操作图标（SVG，原创）
```

- 模块之间只通过**事件总线**通信（`core` 发出「击杀」「开波」「购买」等事件，`render`、`audio`、`ui` 各自订阅）。现在的 `g.events` 已经是这个雏形。
- `core` 与 `content` 不依赖浏览器，所有数值和规则都能在 CI 里测。

### 需要负责人拍板的三个决定

1. **引入构建步骤（esbuild，毫秒级，一条命令）**，改用 ES 模块。
   - 好处：能拆成上面的小文件；三方同时改动时冲突大幅减少；可以做单元测试。
   - 代价：推翻 `AGENTS.md` 硬规则「游戏本身没有构建步骤」。`npm run dev` 会自动边改边构建，日常使用感觉不到。
2. **界面从 Canvas 手画改为 HTML + CSS 叠加层**。
   - 好处：整备页放物件图、文字自动换行、英文排版、手柄焦点导航、设置页都变得简单。这是满足第 6 条和上架需求最省力的办法。
   - 代价：界面代码基本重写，但会保持现有布局和操作不变。
3. **整备页物件图用 SVG**：代码生成或由 Codex 画原创 SVG，存在 `assets/icons/`。
   - 负责人已批准整备页可以用原创图像。SVG 体积小、清晰、可按品阶换色。

### 质量保障（升级时同步建立）
- 单元测试（`node --test`）：结算、经济、进化、解锁、存档迁移。
- 内容校验：每件道具都有图标、名称、说明和英文文案；数值在合理范围内。
- 视觉回归：`npm run shots` 固定场景截图，与上一版对比。
- 平衡回归：每个 PR 跑一次小规模平衡机器人，各英雄平均波数偏离过大就报警。
- 性能预算：CI 记录帧时间，超标报警。

## 四、执行顺序（一次推进，每步都跑全套测试）

| 步骤 | 内容 | 是否改变玩法或画面 |
|---|---|---|
| 0 | 对账：`npm run sync`；合入 Cursor 本地改动和 PR #4 | 带入已做的内容 |
| 1 | 架构迁移：拆模块、事件总线、构建、存档版本化；行为保持不变，用截图和平衡机器人证明 | 不变 |
| 2 | 界面改为 HTML 叠加层，同时做整备页图像化（需求 8） | 界面变好看，操作不变 |
| 3 | 玩法：进化与难度曲线收尾（含第 9–11 波硬墙）、商店威胁预告、新兵种（需求 1–7） | 变 |
| 4 | 美术：圣火神龛、战斗配色、HUD 统一（需求 9–11） | 变 |
| 5 | 声音：音量平衡、音效逐类打磨（需求 13–15） | 变 |
| 6 | 上架项（等负责人要求） | — |

每一步单独提交，失败可以单独回退；每步结束更新 `docs/PLAYER-LOG.md` 里对应条目的状态。
