# 圣火守护者 Flame Guardian · 美术圣经 v0.1（FG-ART-001）

状态：目标定义，不代表已经实现。所有概念图只是目标画面。
标注：【A】= 全代码生成可以做到；【B】= 需要导入手工模型、贴图或字体；【A+】= A 路线加一个很小的外部文件例外。

## 1. 风格定位
一句话：**夜里唯一的暖光——粗轮廓、低多边形的绘本奇幻守村。**
画面核心是冷色的夜包围一团暖色的圣火。所有造型都要"胖、短、剪影清楚"，远看像桌面上的手工木雕玩具。

参考方向（只借鉴方向，不照搬任何造型、配色表或 UI）：
- 火光照亮黑夜、光圈即安全区的氛围：参考 Kingdom Two Crowns 的明暗逻辑。
- 极简几何也能一眼认出单位：参考 Bad North 的轮廓处理。
- 白天暖色田园的饱和度控制：参考 Dorfromantik。
- HUD 边框的戏剧感和可读性：参考 Hades 的层级处理。
【A】风格本身可以用程序模型加风格化着色器实现。

## 2. 色彩与昼夜规则
主色（圣火）：圣火金 #FFB547，余烬橙 #E8702A。整个画面最亮、最暖的颜色只给圣火和英雄。
辅色（村落）：暖土 #C9A27A，草地 #6F9A4E，屋顶赭红 #A8483A，木色 #7A5234。
冷色（夜与敌）：夜蓝 #1E2A4A，月青 #5FA8C8，敌紫 #6B3FA0，敌眼红 #FF3B3B（只用在敌人眼睛和攻击预警上）。

规则：
- 白天：暖色主光（太阳偏金），阴影偏冷蓝紫，绝不用纯黑或纯灰阴影。【A】
- 夜晚：环境整体压到夜蓝，亮度约为白天的 35%；圣火产生一个半径明确的暖光圈，光圈外是敌人的地盘。【A】
- 敌人永远是冷色身体加红色眼睛或边缘光，英雄和我方建筑永远偏暖。玩家靠冷暖就能分敌我。【A】
- 同一画面里高饱和色不超过 3 块，其余全部降饱和，避免现在"每样东西都很鲜艳所以什么都不突出"的问题。【A】

## 3. 轮廓规则（缩到 Steam 缩略图也要认得出）
验收方法：把画面缩到 231×87 并转成纯黑剪影，英雄、圣火、塔、敌人四类仍能分辨。
- 英雄：在 960×540 画面里身高不少于 48 像素（大约是现在的 2.5 倍）。头身比 1:2，大帽子或头盔、披风、夸张武器三件里至少有两件，形成独有剪影。英雄脚下有一圈暖色光环。【A】
- 敌人：三种体型必须差异明显，分别是小而圆（杂兵）、高而带尖刺（精英）、宽而矮重（重甲）。每种剪影一眼能分，身高分别约为英雄的 0.6、1.1、1.4 倍。【A】
- 建筑：屋顶要夸张（高尖顶或厚茅草），墙体比屋顶窄，形成"蘑菇"式剪影。【A】
- 塔：每种塔的顶部造型必须不同（弓塔是尖顶瞭望台，法塔是悬浮水晶，炮塔是粗短炮口），靠顶部识别，不靠颜色。【A】
- 描边：所有单位和建筑加深色外轮廓线（反向外壳法），角色 2 像素、建筑 1.5 像素，颜色是物体本色压暗，不用纯黑。【A】

## 4. 材质语言
- 基础：卡通三段色阶着色（亮面、中间调、暗面），加顶点色渐变（底部偏暗、顶部偏亮），加冷色边缘光。【A】
- 石头、木头、茅草：用程序噪声做轻微的颜色斑驳和笔触感，不追求写实纹理。【A】
- 圣火：程序粒子加自发光核心加热浪扭曲，是全场唯一允许强泛光的物体。【A】
- 手绘贴图级别的细节（木纹、布料花纹、石缝）：【B】。A 路线用色阶加噪声替代，精细度会低一档，但风格统一。

## 5. 光照与后处理
- 主光一盏平行光加半球环境光，阴影开启并柔化。【A】
- 环境光遮蔽：必须加（Three.js 自带 SAO 或同类代码实现），让建筑和单位"落地"，解决现在的漂浮感。【A】
- 泛光：阈值拉高，只让圣火、法术和敌人眼睛发光。现在的全屏泛光要关掉，它是画面发白的主因。【A】
- 色调映射用 ACES，加轻微暗角把视线收向画面中心。【A】
- 夜晚加低矮的冷色雾，远处敌人先以红眼出现、再显出身形，制造压迫感。【A】

## 6. UI 风格
- 边框：深色木框加金色描边，四角有小的火焰或铆钉装饰，用 SVG 或 Canvas 在代码里画成九宫格，不用默认圆角矩形。【A】
- 字体气质：标题用有衬线、略带手刻感的字体，正文用清晰的无衬线字体。系统字体做不出这种气质，需要导入字体文件。建议用开源授权（OFL）的字体，比如思源宋体或 Noto Serif SC 做标题、思源黑体做正文。【A+】
- 图标：统一线宽、统一的金色描边剪影风格，用 SVG 在代码里画。【A】
- HUD 层级：
  1. 第一层（常驻）：左上是圣火生命值（火焰形状的血条），右上是波次和倒计时，底部中间是建造栏。
  2. 第二层（情境）：选中单位时，在画面右下弹出信息卡。
  3. 第三层（提示）：教程和提示放在顶部中间的横幅或右侧的卷轴卡片里。**任何提示都不能盖住画面中央 50% 的战场区域。**
- 敌人来袭预警：用画面边缘的红色箭头指向来袭方向，不用弹窗。【A】

## 7. 三张目标画面：构图与验收
### 7.1 标题页
构图：夜景，圣火位于画面下三分之一处、偏中间，火光照亮周围一圈村屋；远景是冷蓝色的山和森林，森林边缘有几双红眼。英雄背对镜头站在火旁。标题 Logo 放在上三分之一处，菜单竖排在左侧或右侧。
验收：
- 缩略图里一眼能看到"暖火对冷夜"。
- 英雄剪影清楚，辨认得出。
- Logo 的字体是专门导入的字体，不是系统字体。
- 菜单用木框金边样式。
### 7.2 白天对局
构图：斜 45 度俯视，圣火在画面正中，村屋围成一圈，两三座不同的塔分布在村子边缘，英雄在中景清一小群杂兵。HUD 按上面的三层规则摆放。
验收：
- 英雄身高不少于 48 像素，是画面里最醒目的单位。
- 三种塔靠顶部造型就能区分。
- 阴影偏冷色，建筑脚下有环境光遮蔽。
- 画面中央没有被 UI 遮挡。
### 7.3 夜战高潮
构图：同样的机位，夜蓝压暗全场。圣火光圈是画面的焦点；光圈边缘，敌人从两到三个方向涌入（三种体型都要出现）；塔在开火，法术有发光效果；英雄在光圈边缘放大招。
验收：
- 冷暖分区清楚：光圈内是暖色，光圈外是冷色。
- 只有火、法术和敌人眼睛在发光，画面没有被洗白。
- 在敌人很多的情况下，英雄仍然一眼能找到。
- 缩到 231×87 仍能读出"火在中间，敌人从外面包围"。

## 8. 推荐
**选 A，外加一个开源字体文件的例外（A+）。** 理由：
1. 现在显得 low 的主要原因（没有轮廓、没有描边、全屏泛光、单位太小、UI 盖住战场）都能用着色器、后处理和比例调整解决，不需要手工模型。
2. 全程序生成能保持风格统一，也方便后续调参和批量生成新单位，工作量可控。
3. 系统字体是 A 路线唯一解决不了的硬伤，引入一个 OFL 授权字体就能补上，版权风险低。
