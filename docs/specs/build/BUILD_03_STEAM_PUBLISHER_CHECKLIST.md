## 3. 测试包提交流程

### 3.1 Steam 测试包

1. PR 合入 `main` 后，取该提交 CI 产出的 `win-<短SHA>` 产物（BUILD-02 §2.5），核对回执里的 SHA-256。
2. Build/CI 在本机用 `steamcmd` 执行 `app_build_<AppID>.vdf`，构建描述写 `<短SHA> <日期>`。
3. 在后台把该构建设到 `internal` 分支（**不碰 default 分支**）。
4. 在 PR 或测试群里贴：构建号、短 SHA、回执 JSON。
5. 游戏测试切到 `internal` 下载，按 M0 / M1 冒烟清单跑，回执写入 `docs/AUDIT.md`。
6. 发现问题：后台把 `internal` 指回上一个构建（回滚 = 换指针，不重新上传）。

### 3.2 发行商测试包

1. 取 CI 的 Android 构建，mobile 目标，`--ads <publisher>`；发布版用 P13 的上传密钥签名（调试包不能交给发行商）。
2. 游戏测试跑冒烟：冷启动 ≤ 5 秒、没看完不发奖、战斗中 0 广告、埋点事件到达发行商后台（Bible §8 M1-1、M1-2）。
3. 按发行商要求的方式提交（其后台上传 / 商店内部测试轨道 / TestFlight），具体方式在 P1、P2 沟通后补进本节。
4. 记录：构建号、短 SHA、SHA-256、提交时间、发行商回执。
